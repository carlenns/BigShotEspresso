PROJECT NAME: BigShotEspresso

Build and revise this app as BigShotEspresso, using my existing Coffee Log system as the foundation.

BigShotEspresso is not a generic coffee journal. It is an espresso logging, filtering, comparison, and repeatability platform.

The app should help users answer:

- What produced my best shots?
- How do I reproduce them?
- What changed?
- Which beans, bags, recipes, and equipment setups work best?
- What shot style do I personally prefer?

The brand/domain is:

BigShotEspresso
bigshotespresso.com

Display the name prominently but tastefully. The app should feel premium, practical, and espresso-focused.

--------------------------------------------------
CORE PRODUCT PHILOSOPHY
--------------------------------------------------

The primary value is not charts.

The primary value is:

- Fast logging
- Filtering
- Comparison
- Similar-shot lookup
- Reference-shot analysis
- Bean/bag performance
- Personal taste discovery
- Reproduction of successful shots

Charts are useful, but secondary.

Do not overbuild decorative dashboards before the filtering and analysis workflow is solid.

- Pour time
- Scale time
- Rating
- Preference rating
- Notes

Precision requirements:

- Ratings must support hundredths of a point.
  Example: 8.78, 7.42, 9.05

- Preference ratings must also support hundredths.
  Example: 8.65

- All coffee weights should support tenths of a gram.
  Example: 18.3g, 35.4g

- Grind time / dose time should support tenths of a second.
  Example: 8.1 sec

- Pour delay, pour time, and scale time may support tenths if entered, but whole seconds are acceptable.

Dose interpretation rule:

Dose means actual basket dose, not total grinder output.

If initial grind output differs from actual basket dose due to spillage, trimming, overflow, top-up, or removal, analysis should use actual basket dose.

Track grinder-output discrepancy separately.

Reference shot logic:

A reference shot does not have to be a favourite.

It means the shot is mechanically useful and representative.

However, if the shot is unpleasant due to likely extraction fault, it should not automatically be considered reference-worthy.

Support candidate/reference distinction if useful:

- Reference Candidate
- Confirmed Reference
- Not Reference

--------------------------------------------------
IMPORT TOOLS
--------------------------------------------------

BigShotEspresso is not based on CSV import as its normal workflow.

It should have its own database and native entry system.

CSV import is optional for users who already have historical data.

Support optional imports:

- CSV
- Airtable export
- Spreadsheet export

Import requirements:

- Import all rows
- Import all columns where possible
- Do not sample
- Do not invent seed records
- Do not generalize from partial data
- Show an import audit

Import audit should show:

- Row count
- Column count
- Earliest date
- Latest date
- Reference shot count
- Bag count
- Missing field warnings
